# Section & variant catalog

Generated by `pnpm variants:catalog` from the platform's own schemas — **do not edit by hand**; re-run it instead.

How to use it when writing `site.json`:

- `type` must be one of the section types below. Your own section (`"variant": "u:@<key>"`) is a WVF file for that type: its `content` takes the type's **base fields** (plus any extension fields your file declares). A field marked `?` or `= default` may be left out; everything else is required.
- The variant tables list the **platform** variants. Use one only where WVF cannot do the job (an embedded `map`, a blog `post`): then `variant` must be exactly one of that type's ids (omit it to get the first), and `content` also takes that variant's **extra fields**.
- Types marked *siteSections* are chrome (navbar, banner, footer): they go in `siteSections`, never in a page. *Automatic* types cannot be written.
- The "fits" column is still a good brief for your own design: a hero that needs a photo is wrong for a user with none, a portrait-led hero is for a site about one person.
- `npx @webto-id/variant-check site <folder>` checks every section's `content` against exactly these rules.

Notation: `?` = optional, `= x` = default value, `{a, b?}[]` = array of objects.
